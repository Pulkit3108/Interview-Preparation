In .NET, what is the purpose of the Task.Run method?
In .NET, the Task.Run() method is used to queue work to run on a separate thread, typically from the thread pool. It is a convenient way to offload CPU-bound work to a background thread, allowing the main thread (often the UI thread in desktop applications) to remain responsive.
Describe the lifetime of dependencies in a Dependency Injection (DI) container.
In .NET, the Dependency Injection (DI) container manages the lifetime of dependencies to control how long instances of services are kept alive and reused. There are three main lifetimes that you can specify when registering services in the DI container:
Transient: New instance per request. Use for lightweight, stateless services.
Scoped: Single instance per scope (e.g., per HTTP request). Use for services that maintain state within a single request.
Singleton: Single instance for the entire application lifetime. Use for services that maintain shared state and are expensive to create.
In .NET, what is the main purpose of the HttpClientFactory introduced in .NET Core 2.1?
The main purpose of the HttpClientFactory introduced in .NET Core 2.1 is to provide a centralized and efficient way to create and manage instances of HttpClient. It addresses several issues associated with the traditional use of HttpClient, such as resource management, configuration, and dependency injection.
In .NET Framework, which design pattern is often used with DbContext to implement the Unit of Work pattern?
In the .NET Framework, the Repository Pattern is often used in conjunction with the Unit of Work Pattern to manage DbContext instances. These patterns help in abstracting the data access layer, promoting a clean separation of concerns, and making the code more testable and maintainable
Explain a bit about Event Sourcing, CQRS, Message Bus, and Mediatr
Event Sourcing is a pattern that captures all changes to an application's state as a sequence of immutable events. These events are stored in an event log or journal, and the current state of the application is determined by replaying these events
Command Query Responsibility Segregation (CQRS) pattern is an architectural pattern in C# that separates read and write operations for a data store into separate models
Message Bus is a framework that allows clients to publish and receive messages, and is responsible for error handling and connection resilience.
Mediatr is a popular .NET library that implements the mediator pattern, which helps reduce dependencies between objects and promotes loose coupling. It's useful for applications that require low coupling between components.
What is IIS and what is it used for?
Internet Information Services, also known as IIS, is a Microsoft web server that runs on the Windows operating system and is used to exchange static and dynamic web content with internet users. IIS can be used to host, deploy, and manage web applications using technologies such as ASP.NET and PHP.
What are physical, logical, and virtual cores?
Physical cores These are actual hardware units that are contained on a chip and occupy a single socket on the motherboard. A physical processor is also known as a "real" CPU. 
Logical cores These are virtual cores that allow a single physical core to divide its resources and handle two sets of instructions simultaneously. This allows a CPU to work on more tasks at once. Logical cores are a concept used to describe how operating systems view processors that use Simultaneous Multithreading (SMT). 
Virtual cores Also known as vCPUs, these are a term used by cloud IaaS providers to describe the computing power of the services they provide. vCPUs are not physical cores, but rather logical processing power. They represent the amount of time a virtual machine gets on a logical processor
What is the Application Life Cycle?
The application life cycle is a choreographed sequence of stages that takes place from the moment a user initiates a request until the application sends back a response.
	• Application start
	• Object creation
	• HTTP application
	• Initialization Stage
	• Execution and Event Handling
	• Rendering the User Interface
	• Postback Handling
	• Cleanup, Unloading, and Dispose
	• Application end
