What is Docker and what is the main principle behind Docker technology?
Docker: An open-source platform for automating the deployment, scaling, and management of applications using containerization.
Main Principle: Containerization, which involves encapsulating an application and its dependencies into a container.
Isolation: Containers provide isolated environments for applications, ensuring they run independently.
Portability: Containers can run consistently across different environments.
Efficiency: Containers are lightweight and share the host OS kernel, making them more efficient than VMs.
Consistency: Containers ensure applications run consistently across different environments.
Scalability: Containers can be easily scaled up or down to handle varying workloads.
Key Components: Docker Engine, Docker Images, Docker Containers, Dockerfile, Docker Hub
Explain the 3 innovations behind Docker?
Docker Image (Build):
Innovation: Provides a lightweight, standalone, and executable package that includes everything needed to run an application.
Key Characteristics: Layered file system, immutability, and Dockerfile for building images.
Example: A Dockerfile specifying the base image, application code, dependencies, and configuration.
Docker Registry (Ship):
Innovation: A storage and distribution system for Docker images, enabling sharing and distribution across different environments.
Key Characteristics: Public and private registries, versioning, and distribution.
Example: Pushing and pulling images to and from Docker Hub.
Docker Container (Run):
Innovation: A runtime instance of a Docker image, providing isolated, portable, and efficient environments for running applications.
Key Characteristics: Isolation, portability, and efficiency.
Example: Running, listing, and stopping Docker containers.
Why Docker is needed. What makes it so fast?
Why Docker is Needed:
Isolation: Provides isolated environments for applications, preventing conflicts and ensuring stability.
Environment Consistency: Ensures applications run consistently across different environments, eliminating the "works on my machine" issue.
Speed of Deployment: Accelerates the development, testing, and deployment processes, allowing businesses to deliver software faster.
What Makes Docker So Fast:
Docker Image (Build): Lightweight, standalone packages with a layered file system and immutability.
Docker Registry (Ship): Storage and distribution system for Docker images, supporting public and private registries and versioning.
Docker Container (Run): Runtime instances of Docker images that provide isolated, portable, and efficient environments for running applications.
What is the difference between Docker and Kubernetes
Docker:
Purpose: Docker is a platform for developing, shipping, and running applications inside containers.
Functionality: It allows you to package an application and its dependencies into a container, ensuring that it runs consistently across different environments.
Components: Docker Engine, Docker Hub, Docker Compose, etc.
Kubernetes:
Purpose: Kubernetes is an open-source container orchestration platform designed to automate deploying, scaling, and operating containerized applications.
Functionality: It manages clusters of containers, providing features like load balancing, scaling, rolling updates, and self-healing.
Components: Kubernetes Master, Nodes, Pods, Services, Deployments, etc.
How do the kubelet and container runtime writes for the following:
In Kubernetes, the kubelet is the primary node agent that runs on each node. It interacts with the container runtime to manage the lifecycle of containers. The way kubelet and container runtime write logs and manage processes can differ based on whether the underlying machine uses systemd or another init system.
a. Machines with systemd
Service Management: Both kubelet and container runtime are managed as systemd services.
Logging: Logs are managed by systemd and can be accessed using journalctl.
b. Machines without systemd
Service Management: Both kubelet and container runtime are managed using init scripts or other service management tools provided by the init system (e.g., sysvinit, upstart).
Logging: Logs are typically written to traditional log files (e.g., /var/log/kubelet.log, /var/log/docker.log).


What is the difference between Centralized and distributed version control?
Centralized Version Control Systems (CVCS):
Single Repository: One central repository.
Network Dependency: Requires network access for most operations.
Simpler Model: Easier to understand and manage.
Examples: Subversion (SVN), Perforce, CVS.
Advantages: Simplicity, centralized access control, consistency.
Disadvantages: Single point of failure, network dependency, scalability issues.
Distributed Version Control Systems (DVCS):
Multiple Repositories: Each developer has a full copy of the repository.
Local Operations: Most operations are local, reducing network dependency.
Complex Model: More complex but offers greater flexibility.
Examples: Git, Mercurial, Bazaar.
Advantages: Resilience, performance, flexibility, better collaboration.
Disadvantages: Complexity, higher storage requirements, consistency challenges.
What is the difference between git merge, rebase and squash?
git merge:
Purpose: Combines the changes from one branch into another.
Functionality: Creates a new commit that includes the changes from both branches.
Usage: git merge <branch-name>
Result: Maintains the history of both branches, resulting in a merge commit.
git rebase:
Purpose: Reapplies commits from one branch onto another.
Functionality: Moves or combines a sequence of commits to a new base commit.
Usage: git rebase <branch-name>
Result: Creates a linear history by applying changes from one branch on top of another, avoiding merge commits.
git squash:
Purpose: Combines multiple commits into a single commit.
Functionality: Used during a rebase to merge several commits into one.
Usage: git rebase -i <commit-hash> and then mark commits as squash or s
Result: Simplifies the commit history by reducing the number of commits.
What is the difference between git fetch and git pull?
git fetch:
Purpose: Downloads changes from the remote repository without merging.
Operation: Updates remote-tracking branches.
Usage: Review changes before merging.
Example: git fetch origin
git pull:
Purpose: Downloads and merges changes from the remote repository.
Operation: Combines git fetch and git merge.
Usage: Quickly update your local branch.
Example: git pull origin main


What is Branching Strategy?
Branching Strategy: A set of guidelines and practices for managing branches in a version control system.
Common Branching Strategies:
Git Flow: Uses multiple branches for different purposes, including main, develop, feature/*, release/*, and hotfix/*.
GitHub Flow: Uses short-lived feature branches and a single long-lived main branch, designed for continuous delivery.
GitLab Flow: Combines ideas from Git Flow and GitHub Flow and introduces environment branches, supporting CI/CD.
Choosing a Branching Strategy: Depends on factors like team size, project complexity, release cycle, and CI/CD requirements
